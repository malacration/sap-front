Relatórios

Crie relatórios pela própria tela, sem depender de deploy. Você escreve uma consulta e um layout; o sistema valida, mostra o resultado e publica para quem você escolher.

O que é

A tela de Relatórios tem duas abas. Em Executar qualquer usuário roda os relatórios liberados para o seu papel e baixa em PDF, CSV ou vê na tela. Em Criar / Editar — visível apenas para administradores — você monta relatórios novos.

Por que não precisa de deploy

O relatório é dado, não código: fica guardado no banco, com histórico de versões. Publicar e voltar atrás são operações imediatas.

Um relatório são dois arquivos

ArquivoPara que serve
.yaml Os dados: qual consulta rodar, quais filtros o usuário preenche, quem pode ver, quais colunas aparecem.
.hbs A aparência: o HTML que vira o PDF ou a tela.

A consulta SQL mora dentro do .yaml, no campo consulta.sql. Na tela há um editor dedicado a ela, mas o arquivo continua sendo um só.

Exemplo completo: lista de colaboradores

O relatório mais simples possível que ainda ensina o mecanismo: lista os colaboradores admitidos num período, com nome, cargo e data de admissão.

Copie e adapte

Cole os dois blocos abaixo nos editores da aba Criar / Editar, clique em Validar e depois em Pré-visualizar. Em menos de um minuto você tem um relatório funcionando.

A consulta (SQL)

Os colaboradores ficam na tabela OHEM. Note o :dataInicio e o :dataFim: são os filtros que o usuário preenche na tela.

SQL — vai dentro de consulta.sql 
SELECT
    H."empID"       AS MATRICULA,
    H."firstName"   AS NOME,
    H."lastName"    AS SOBRENOME,
    H."jobTitle"    AS CARGO,
    H."startDate"   AS ADMISSAO
FROM SBOGRUPOROVEMA.OHEM H
WHERE H."startDate" >= :dataInicio
  AND H."startDate" <= :dataFim
ORDER BY H."startDate" DESC

Três regras que o sistema exige

  • Sempre SELECT. Nada de alterar dados.
  • Tabela com o schema na frente — SBOGRUPOROVEMA.OHEM, nunca só OHEM.
  • Sem comentários no SQL, e uma consulta só.

Todo valor que varia vira :nome. Nunca escreva a data direto na consulta — além de travar o relatório numa data fixa, é o que abre brecha de segurança.

O arquivo .yaml

Junta a consulta, os filtros e as permissões:

relatorio.yaml 
# O número do relatório é gerado pelo sistema ao salvar; o nome é só o título.
nome: Meu relatório
descricao: Descreva em uma linha o que este relatório responde

# Quem enxerga este relatório na aba Executar
papeis: [admin]

# Cada item vira um campo do formulário.
# O `nome` precisa ser IGUAL ao :nome usado no SQL.
parametros:
  - nome: dataInicio
    tipo: date
    rotulo: Admitidos a partir de
    obrigatorio: true
  - nome: dataFim
    tipo: date
    rotulo: Admitidos até
    obrigatorio: true

consulta:
  # Regras: sempre SELECT, tabela com o schema na frente, sem comentários,
  # e todo valor variável como :parametro.
  sql: >
    SELECT H."empID" AS MATRICULA, H."firstName" AS NOME,
           H."lastName" AS SOBRENOME, H."jobTitle" AS CARGO,
           H."startDate" AS ADMISSAO
    FROM SBOGRUPOROVEMA.OHEM H
    WHERE H."startDate" >= :dataInicio AND H."startDate" <= :dataFim
    ORDER BY H."startDate" DESC
  maxRows: 2000

# `campo` é o nome que a consulta devolve (o AS)
colunas:
  - { campo: MATRICULA, titulo: Matrícula, tipo: texto }
  - { campo: NOME,      titulo: Nome,      tipo: texto }
  - { campo: SOBRENOME, titulo: Sobrenome, tipo: texto }
  - { campo: CARGO,     titulo: Cargo,     tipo: texto }
  - { campo: ADMISSAO,  titulo: Admissão,  tipo: data }

formatos: [pdf, html, csv]

O erro mais comum

Filtro declarado em parametros que não aparece no SQL — ou o contrário. O sistema recusa os dois casos e diz exatamente qual nome está sobrando ou faltando.

O arquivo .hbs

É HTML comum. O que muda é {{ }} para inserir valores e {{#each linhas}} para repetir uma linha por registro.

template.hbs 
<style>
  @page { size: A4; margin: 1.5cm }
  body  { font-family: Helvetica, Arial, sans-serif; font-size: 11px; color: #222 }
  h1    { font-size: 18px; margin: 0 0 4px }
  .sub  { color: #666; margin-bottom: 12px }
  table { width: 100%; border-collapse: collapse }
  thead { display: table-header-group }   /* repete o cabeçalho a cada página */
  th    { background: #eee; text-align: left; padding: 6px; border-bottom: 2px solid #ccc }
  td    { padding: 5px 6px; border-bottom: 1px solid #eee }
</style>

<h1>{{meta.nome}}</h1>
<div class="sub">De {{params.dataInicio}} até {{params.dataFim}}</div>

<table>
  <thead>
    <tr>
      {{#each colunas}}<th>{{titulo}}</th>{{/each}}
    </tr>
  </thead>
  <tbody>
    {{#each linhas}}
    <tr>
      <td>{{MATRICULA}}</td>
      <td>{{NOME}} {{SOBRENOME}}</td>
      <td>{{CARGO}}</td>
      <td>{{ADMISSAO}}</td>
    </tr>
    {{else}}
    <tr><td colspan="4">Nenhum registro no período.</td></tr>
    {{/each}}
  </tbody>
</table>

Dois detalhes que valem lembrar

  • {{else}} dentro do {{#each}} aparece quando não há nenhum registro — melhor que uma tabela vazia.
  • thead { display: table-header-group } faz o cabeçalho se repetir em todas as páginas do PDF.

Agrupamento e totais

O layout não faz conta. Subtotais e total geral são calculados pelo sistema, sem erro de centavos. Você só declara no .yaml o que quer:

relatorio.yaml 
agrupar: [VENDEDOR]          # quebra por vendedor (até 3 níveis)
colunas:
  - { campo: VENDEDOR, titulo: Vendedor, tipo: texto }
  - { campo: NOTAS, titulo: Notas, tipo: numero, total: sum }
  - { campo: TOTAL, titulo: Total, tipo: moeda,  total: sum }

total é a operação feita na coluna: sum (soma), avg (média), min (mínimo), max (máximo), para colunas de número, moeda ou percentual, e count (contagem, qualquer coluna). O campo usado em agrupar precisa estar em colunas.

template.hbs 
{{#each grupos}}
  <tr><td colspan="3">{{titulo}}: {{valor}}</td></tr>
  {{#each linhas}}<tr><td>{{NOME}}</td><td>{{NOTAS}}</td><td>{{TOTAL}}</td></tr>{{/each}}
  <tr><td>Subtotal</td><td>{{totais.NOTAS}}</td><td>{{totais.TOTAL}}</td></tr>
{{/each}}
<tr><td>Total geral</td><td>{{totais.NOTAS}}</td><td>{{totais.TOTAL}}</td></tr>

Ordem dos grupos

As linhas são reunidas pelo valor do campo, então um grupo nunca se parte. O ORDER BY do SQL só define a ordem em que os grupos aparecem. No CSV, cada grupo termina numa linha de subtotal e o arquivo termina no total geral.

Resumos: o total do vendedor em todas as filiais

Com agrupar: [FILIAL, VENDEDOR] o vendedor tem subtotal dentro de cada filial, mas não o total dele somando todas. Para esse outro corte use resumos: 

resumos:
  - titulo: Total por vendedor (todas as filiais)
    por: [VENDEDOR]

O template recebe resumos, cada um com titulo e grupos (os mesmos totais das colunas), para montar um quadro no fim.

Para ver funcionando, use Carregar exemplo no topo da tela de autoria: Vendas por vendedor (agrupado, com totais) e Vendas por filial e vendedor (dois níveis), que traz o resumo.

Logo no cabeçalho

A logo do sistema entra sozinha no PDF e no HTML: a tela a envia junto ao gerar o relatório. No layout, use:

template.hbs 
<style>
  .logo { float: right; max-height: 42px; max-width: 160px; margin-left: 12px }
</style>

{{#if meta.logo}}<img class="logo" src="{{meta.logo}}" alt="Logo">{{/if}}

Por que só assim

O servidor nunca busca imagem de fora ao gerar o PDF, então <img src="https://..."> é recusado. A logo vai embutida no pedido, e {{meta.logo}} é a única expressão aceita em src. O {{#if}} evita imagem quebrada quando o relatório é gerado pela API, sem logo. Os exemplos prontos já vêm com isso.

Como publicar

1 Validar
Confere tudo sem salvar nada. Se houver problema, aparecem todos de uma vez, com o campo exato e a linha. Use quantas vezes quiser.
2 Salvar rascunho
Guarda uma versão. Rascunho não aparece para os usuários — só para você.
3 Pré-visualizar
Roda de verdade, com dados reais, mas sem publicar. É aqui que você confere se os números fazem sentido.
4 Publicar
A partir daqui o relatório aparece na aba Executar para quem tem os papéis listados em papeis.

Errou depois de publicar?

Versões antigas nunca são apagadas. Em Histórico você volta para qualquer versão anterior num clique — o conteúdo não é sobrescrito, só muda qual está no ar.

Referência dos campos

Tipos de filtro (parametros[].tipo)

TipoVira na tela
textocampo de texto
numerocampo numérico
dateseletor de data
datetimedata e hora
booleanocaixa de marcar
listalista suspensa (exige opcoes)
filialcadastro de filiais; envia Bplid/BPLID inteiro
vendedorbusca de vendedores; envia SalesEmployeeCode inteiro (SlpCode)
parceiro_negociobusca de parceiros; envia CardCode textual
itembusca de itens; envia ItemCode textual
localidadebusca de localidades; envia Code textual

Cadastros e listas aceitam multiplo: true: envie um array de códigos para IN (:parametro). Sem essa opção, envie um código para = :parametro. O valor padrão segue a mesma cardinalidade.

Obrigatórios exigem seleção. Opcional vazio envia null; IN (NULL) não retorna linhas e não significa “todos”. Para “todos”, declare um booleano separado: :todos = TRUE OR T0."BPLId" IN (:filiais). Não use :filiais IS NULL com arrays.

As buscas usam somente cadastros existentes. Não há SQL de opções configurável. JOINs continuam na consulta; os seletores não substituem autorização.

Erros comuns

MensagemO que fazer
Parâmetro não usado / ausente O nome em parametros tem que ser idêntico ao :nome do SQL. Confira maiúsculas.
Tabela não permitida Escreva com o schema: SBOGRUPOROVEMA.OHEM. Se a tabela não estiver liberada, peça a liberação.
SQL com comentário Remova -- e /* */ da consulta.
Uso de {{{ }}} Troque por {{ }}. A forma tripla não protege contra conteúdo malicioso vindo dos dados.
Recurso externo proibido Imagens precisam estar embutidas no próprio arquivo. Endereços http:// e file:// não são aceitos.
Resultado muito grande Restrinja o período ou os filtros. O relatório não é entregue pela metade de propósito — número incompleto engana.

Deixar uma IA criar o relatório

Na aba Criar / Editar há o botão Baixar instruções para IA. O pacote tem duas pastas: uma para o Claude Code e outra para configurar um GPT no ChatGPT.

Junto, gere um token na mesma tela. Ele permite que a IA valide, crie rascunho e pré-visualize.

A IA não publica

O token não tem permissão para publicar — de propósito. Publicar define quem passa a enxergar aqueles dados, e essa decisão continua sendo de uma pessoa. A IA prepara; você confere na pré-visualização e libera.

Guarde o token na hora

Ele aparece uma única vez. Não há como recuperá-lo depois — se perder, revogue e gere outro.
